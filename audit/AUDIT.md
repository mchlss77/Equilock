### Яка зміна в коді дала який результат

**Accessibility 94 → 100**
- **`color-contrast`:** 0 → пройдено. `.text-primary` переведено на змінну `--c-primary-text` (#818CF8 у темній темі, #4F46E5 у світлій), фон кнопок — #4F46E5. Це `css/tailwind.css` і `css/style.css`; заголовки на `about.html` використовують той самий клас. На головній «до» падали бейджі «01 / 04».
- **`target-size`:** 0 → пройдено. Мобільне правило 48×48 px для посилань, кнопок і полів у `css/style.css`. *Застереження:* на головній «до» падали точки Swiper, а на `about.html` слайдера немає, тож саме їхнє виправлення (ціль 48×48 на `::before`) цей звіт не підтверджує.
- **Без впливу на цей звіт, але виправлено:** `aside` → `div` у шапці, унікальні назви регіонів таблиць, кільце фокуса для полів з `outline-none`, поля 16 px на mobile — усе за axe-прогоном усіх 24 сторінок.

**Best Practices 96 → 100**
- **`image-size-responsive`:** 0 → пройдено. `logo-mark.webp` перегенеровано у 116×120 замість 58×60 (`assets/icons/`). Логотип є в шапці всіх сторінок, тож порівняння коректне.

**SEO 91 → 100**
- **`hreflang`:** 0 → пройдено. Абсолютні URL замість відносних + `x-default` на 24 сторінках.
- **Також додано:** `canonical` (аудит `canonical` пройдено), Open Graph, `robots.txt`, `sitemap.xml`.

**Performance — що з виправлень видно у звіті**
- **`font-display-insight`:** 0 → пройдено. `font-display: block` → `swap` у локальному `all.min.css` Font Awesome.
- **`unused-css-rules`:** Font Awesome (22 KiB невикористаного CSS) зник зі списку. CSS урізано до 46 іконок, що реально використовуються: 73.9 → 11.8 KB.
- **`image-delivery-insight`:** пройдено. *Застереження:* на `about.html` лише hero, який і раніше був у WebP. Конвертація `step*.png` → WebP + `srcset` (−467 KiB на головній) цим звітом не перевірена.
- **`render-blocking`:** 870 → 440 мс. *Застереження:* на `about.html` ніколи не було CSS Swiper / Fancybox, а саме його неблокуюче завантаження давало основну економію на головній. Тут різниця — переважно від іншої сторінки й тротлінгу.
- **FCP / LCP / Performance:** виміряно в desktop-режимі, тому внесок змін у коді від режиму не відокремити.

### Що зробити, щоб порівняння було коректним

1. Задеплоїти поточний код (workflow `.github/workflows/deploy.yml`).
2. Запустити Lighthouse у вікні інкогніто: **Mobile**, сторінка **https://equilock-lovat.vercel.app/** — та сама, що й «до».
3. Зберегти звіт як `audit/lighthouse-after.json` і оновити таблицю вище. Тоді FCP / LCP / Performance стануть порівнянними, а виправлення слайдера (WebP, неблокуючий CSS, точки 48×48) — перевіреними.
