# CLAUDE.md — EQUILOCK

Статичний сайт escrow-платформи: HTML5 + Tailwind (готовий `css/tailwind.css`) + власний `css/style.css` + чистий JS без збирання. Дві мови: українська в корені, англійська в `en/`.

## Правила на час ЛР №11 (калькулятор комісії escrow-угоди)

Ці правила діють для кожного запиту в межах лабораторної роботи №11.

### 1. Журнал промптів — `prompt-log.md`

Після кожного мого запиту **дослівно** дописуй новий рядок у таблицю `prompt-log.md`:

- `№` — наступний порядковий номер;
- `Етап` — коротка назва етапу роботи;
- `Промпт (дослівно)` — текст мого запиту **без скорочень і перефразувань** (переноси рядків → `<br>`, символ `|` екранувати як `\|`);
- `Що зроблено` — короткий підсумок фактично виконаного.

Запис робити **в тому ж відповіді**, де виконано роботу, а не «потім».

### 2. QA-журнал — `qa-log.md`

У `qa-log.md` записувати:

- **результати тестів** — заповнювати колонки «Фактично» та «Як виправлено» в тест-плані;
- **баги** — симптом, кроки відтворення, причина;
- **виправлення** — що саме змінено і в якому файлі;
- **аудити** — підсумки перевірок коду, доступності, консолі.

Тест-план і Happy Path приклади не переписувати без потреби — лише доповнювати фактичними результатами.

### 3. Що не робити

- Не змінювати формулювання моїх промптів у журналі.
- Не вважати задачу виконаною, поки обидва журнали не оновлені.
